How DNS works

DNS turns a name, such as example.com, into a number called an IP address. Your computer needs that number to find the site. A resolver asks a chain of servers until one of them knows the number.

The parts

Browser
Needs the address of a site, and starts the request.
Resolver
Does the lookup work for your computer. Your internet provider usually runs it.
Root server
Knows which server handles each ending, such as .com or .org.
TLD server
Handles one ending, and knows which name server holds each domain.
Name server
Holds the records for a domain, and gives the final address.

The steps

  1. The browser asks the resolver for the address of a name.
  2. The resolver checks its cache. If the answer is not there, it asks a root server.
  3. The root server sends the address of the TLD server for that ending.
  4. The resolver asks the TLD server.
  5. The TLD server sends the address of the name server for the domain.
  6. The resolver asks the name server.
  7. The name server sends the IP address.
  8. The resolver saves the answer and sends it to the browser.

Example

You type www.example.com. The root server points to the .com server. The .com server points to the name server for example.com. That name server gives the IP address, and the browser connects to it.

Limits

This page shows the common case. Real lookups often end sooner, because the resolver and your computer keep recent answers in a cache. Each answer has a time limit, set by the domain owner, after which the cache must ask again.
