How DNS works

The Domain Name System (DNS) turns a name like example.com into an IP address that computers use to find each other. Your device asks a resolver, and the resolver asks a chain of DNS servers until one has the answer. The answer is kept for a short time, so the next request is fast.

The parts

Resolver
A server, often run by your internet provider, that looks up names for your device and keeps answers for reuse.
Root and TLD servers
Servers that know which servers handle each top-level domain, such as .com.
Authoritative server
The server that holds the real records for a domain, including its IP address.
Cache
A short-term store of earlier answers, kept on your device and on the resolver.

The steps

  1. You type example.com in your browser.
  2. Your device checks its own cache. If it has the address, it stops here.
  3. If not, it asks the resolver, which checks its own cache.
  4. If the resolver has no answer, it asks a root server, then the .com server, to find the authoritative server.
  5. The authoritative server sends the IP address for example.com.
  6. The resolver returns the address to your device and keeps a copy for a set time, called the TTL.
  7. Your browser connects to the IP address.

Limits

DNS answers are cached, so a changed record can take minutes or hours to reach everyone. Plain DNS is not encrypted, so others on the network can see the names you look up. DNS over HTTPS or DNS over TLS hides them.
