How Git Branches and Merges Work

A branch is a movable label that points to a commit. A merge joins the work of two branches into one.

Branches

  1. Each commit stores a snapshot and a link to its parent commit.
  2. A branch is a name that points to one commit.
  3. When you make a new commit, the branch name moves to the new commit.
  4. git branch feature makes a new name at the current commit.
  5. git switch feature moves HEAD to that branch, and new commits go there.

Merges

  1. Switch to the branch that must receive the work, for example main.
  2. Run git merge feature.
  3. Git finds the common ancestor of the two branches.
  4. If main has no new commits, Git only moves the main label forward. This is a fast-forward.
  5. If both branches have new commits, Git combines the changes and makes a merge commit with two parents.

Conflicts

  1. A conflict happens when both branches change the same lines.
  2. Git stops and marks the conflict in the file.
  3. You edit the file and keep the correct text.
  4. Run git add on the file, then git commit to finish the merge.
